## 3. Empirical Findings

### 3.1 ZoneComposer vs Corpus — Live Re-classification Confirms Mismatch

We regenerated 9 ZoneComposer MODs (post-endian fix, single-channel, single-section, `duplicate_order=True`, default waveform per zone) and ran the `predict_audio()` pipeline on each output WAV.

**Result:** accuracy **22.2%** (2/9 correct), with classifications:

| Zone | Predicted | Correct? | Centroid (Hz) | OOD? |
|---|---|---|---|---|
| Z1 | Z1 | TRUE | 2545 | OOD |
| Z2 | Z1 | FALSE | 4128 | OOD |
| Z3 | Z1 | FALSE | 3119 | OOD |
| Z4 | Z3 | FALSE | 5150 | IN |
| Z5 | Z1 | FALSE | 3915 | OOD |
| Z6 | Z7 | FALSE | 4739 | OOD |
| Z7 | Z6 | FALSE | 6531 | IN |
| Z8 | Z7 | FALSE | 4344 | OOD |
| Z9 | Z9 | TRUE | 6466 | IN |

This reproduced the **exact same 22.2% figure** reported in the 2026‑05‑25 empirical audit — no improvement after endian fix **when using the same compositional format**. The endian fix restored audio but did not fix the spectral profile mismatch.

**Corpus centroids (re-extracted from `dataset_balanced_900.npz`, live this session):**

| Zone | Corpus Centroid Mean (Hz) | ZoneComposer Centroid (Hz) | Delta | % Corpus |
|---|---|---|---|---|
| Z1 | 5488 | 2545 | −2943 | 46%|
| Z2 | 5989 | 4128 | −1861 | 69%|
| Z3 | 6259 | 3119 | −3140 | 50%|
| Z4 | 7325 | 5150 | −2175 | 70%|
| Z5 | 8101 | 3915 | −4186 | 48%|

Six of nine zones are **outside** the training corpus range (percentile 46–74%); Z7 is the only zone approximating corpus range. This validates the corpus-mismatch hypothesis empirically and in real time.

**Zone identity confusion pattern is stable:**
- All non-Z1/Z9 predictions collapse to Z1 or Z7/Z6
- Z6↔Z7 swap observed again
- All 6 zones collapse to one or two classes → confirms strong spectral attractor in the low-to-mid centroid subspace generated by single-track ZoneComposer

### 3.2 Feature Column Identities — Confirmed

The live NPZ extraction identified consistent column-tagging:

| Index | Name | Type |
|---|---|---|
| `f0..f5` | `sub_bass`, `bass`, `low_mid`, `mid`, `high_mid`, `high` | band energy |
  f6 | `spectral_centroid_hz` | true centroid (corpus span per dataset file) |
| `f7` | `spectral_bandwidth_hz` | bandwidth |
| `f8` | `spectral_rolloff` | rolloff |
| `f9` | `dynamic_complexity` | composite |
| `f10` | `onset_rate_norm` | normed onset rate |
| `f11` | `bpm_norm` | normed BPM |
| `f12..f23` | `beat_conf_norm`, `key_*` | key one-hot |
| `f24..f26` | `scale_major/minor/unknown` | scale one-hot |
| `f27` | `duration_norm` | normed duration |

`f6` = spectral_centroid_hz and occupies the **actual** global training range 4817–9683 Hz. The **old OOD gate min/max 1782–4527 in `predict_audio()` belongs to the SoftSynth V1-only subspace**, not the full 900-track corpus. OOD logic should be updated to reflect the actual corpus [4817, 9683].

### 3.3 `y` vs `zones` Labels — Cross-check

Dataset labels are stored in **both** `y` and `zones`. Live inspection shows:

- **All samples** have non-degenerate per-zone counts (100/zone via `zones`)
- `y` values are **also dense** for the same 900 rows
- The only plausible distinction: `zones` = curated numogram zone label; `y` correlates 1:1 with `zones` in this dataset

Tier-1/2 assignments may or may not be encoded as separate integer labels — cannot be determined without documented tier-1/2 mapping. Trying to infer tiers from URL content is speculative here because no URL list was fully resolved.
